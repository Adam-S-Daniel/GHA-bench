## What was built

A PR label assigner in **Bash**, developed with red/green TDD using **bats-core**, integrated into a **GitHub Actions** pipeline validated with **actionlint** and run end-to-end via **act**.

### Files

| File | Purpose |
|------|---------|
| `label-assigner.sh` | Core script: glob-pattern → label rules engine |
| `label-rules.conf` | Default path-to-label rules (with priorities) |
| `fixtures/*.files` | 5 mock changed-file lists (one per test case) |
| `test/label_assigner.bats` | 20 TDD unit tests of the script logic |
| `test/workflow_structure.bats` | 13 YAML-structure / reference / actionlint tests |
| `test/workflow_act.bats` | 10 end-to-end tests run **through act** |
| `.github/workflows/pr-label-assigner.yml` | The CI/CD workflow |
| `act-result.txt` | Required artifact: full act log + per-case results |

### Script design
- **Glob semantics** (minimatch-style, like `actions/labeler`): `*` stays within a path segment, `**` crosses `/`, `?` one char, `**/` = optional leading dirs. Globs are compiled to anchored EREs.
- **Multiple labels per file** (a file matches several rules; one rule can list comma-separated labels) and **priority ordering** — output is sorted by priority descending, then name ascending, so conflicts resolve deterministically. Highest priority wins per duplicate label.
- **Error handling**: missing/unfound rules file, malformed rule (reports line number), missing args — all exit non-zero with meaningful messages.
- Passes `bash -n` and `shellcheck` cleanly; uses `#!/usr/bin/env bash`.

### Workflow
- Triggers: `push`, `pull_request`, `workflow_dispatch`; least-privilege `permissions`; `RULES_FILE` env var; a `summary` job with `needs: assign` (job dependency).
- A build **matrix** runs all 5 fixtures in a **single `act push`**, each printing `RESULT <case>: [<labels>]`.
