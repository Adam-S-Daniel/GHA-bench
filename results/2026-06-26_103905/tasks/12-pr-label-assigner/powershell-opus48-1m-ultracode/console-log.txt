**Core module** (`src/PRLabelAssigner.psm1`) — side-effect-free, fully unit-tested:
- `ConvertTo-GlobRegex` / `Test-GlobMatch` — glob support with correct directory-boundary semantics (`*`→`[^/]*`, `**`→`.*`, `**/`→optional dir prefix, `?`→`[^/]`), case-sensitive.
- `Get-PRLabels` — unions labels across all matching rules, keeps each label's **highest** priority, returns a de-duplicated set ordered by priority desc then name asc.
- `Import-LabelConfig` / `Get-ChangedFileList` — load + validate inputs with meaningful errors (missing file, bad JSON, missing `rules`/`pattern`/`labels` with the offending index).

**CLI + config + fixtures** — `scripts/Invoke-PRLabelAssigner.ps1` (single PR), `scripts/Invoke-AllFixtures.ps1` (CI entry point), `config/labeler-config.json`, and 5 mock changed-file fixtures (api, docs, mixed, none, tests).

**Workflow** (`.github/workflows/pr-label-assigner.yml`) — triggers (push/pull_request/schedule/workflow_dispatch), least-privilege permissions, shared env, `actions/checkout@v4`, a `test` job running Pester and an `assign-labels` job that `needs: test`, all using `shell: pwsh`.

## TDD trail
Genuine red→green cycles: glob conversion → `Test-GlobMatch` → `Get-PRLabels` → config/changed-file loaders. Each was a failing test first, then minimum code.

## Results
- **`Invoke-Pester ./tests`: 55/55 pass** (27 unit, 17 workflow-structure, 11 act-integration).
- **`actionlint`: exit 0.**
- **`act`: exit 0, both jobs report "Job succeeded".** Every fixture case ran through the workflow and matched its exact expected label set, e.g. `mixed → api,backend,tests,ci,source,documentation,config` and `none → NONE`.
- **`act-result.txt` written** (174 lines): full act log + a clearly-delimited per-case PASS breakdown.
- Used **2 of the 3** allowed `act push` runs (run 1 surfaced a Pester discovery/run scoping bug in the harness; run 2 confirmed all green).

## One design note worth flagging
The task says "for each test case run `act push`" but also caps `act` at 3 runs — contradictory once there are more than 3 cases. I reconciled this by having the `assign-labels` job process **all** fixtures in a single run (one `RESULT case=… labels=…` line each), so every case is genuinely exercised through the pipeline while staying within the run budget. The harness runs `act` once in an isolated temp git repo and asserts each case independently from that output. This is documented in the harness header and README.
