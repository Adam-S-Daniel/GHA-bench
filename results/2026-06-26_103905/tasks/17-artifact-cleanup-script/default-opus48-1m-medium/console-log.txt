## What was built

A **Python** artifact-cleanup planner, developed red→green TDD, plus a GitHub Actions pipeline tested entirely through `act`.

### Core logic — `artifact_cleanup.py`
A pure `build_plan()` function that takes artifacts + a policy and returns `{delete, retain, summary}`. Nothing is ever actually deleted, which makes the logic deterministic and dry-run trivial. Three optional policies with clear precedence:
1. **`keep_latest_per_workflow`** — protective *and* active: keeps the newest N per workflow group, deletes the surplus.
2. **`max_age_days`** — deletes unprotected artifacts older than N days.
3. **`max_total_size_bytes`** — squeezes oldest unprotected survivors until under budget.

Robust input handling via a single `ArtifactError` type (missing fields, negative sizes, bad JSON, missing files, bad timestamps) → clean CLI error messages, no tracebacks. The CLI accepts `--dry-run`, `--now` (deterministic age math), and `--output`.

### Tests (21 passing)
- **`test_artifact_cleanup.py`** (13) — parsing, each policy in isolation, combined behavior, summary, dry-run, error paths. Each was written failing first.
- **`test_workflow.py`** (8) — YAML structure (triggers, permissions, jobs, steps, script reference), path existence, actionlint exit-0, and **2 end-to-end `act` cases** that build a temp git repo, inject per-case fixtures, run `act push --rm`, append delimited output to `act-result.txt`, and assert exit 0, `Job succeeded`, and **exact** summary values (e.g. `Space reclaimed: 700 bytes`).

### Workflow — `.github/workflows/artifact-cleanup-script.yml`
`push`/`pull_request`/`schedule`/`workflow_dispatch` triggers, least-privilege `contents: read`, checkout@v4 + setup-python@v5, runs the script and publishes a job summary. Passes `actionlint` cleanly. I dropped `upload-artifact@v4` (needs an artifact server that may be absent under bare `act`) in favor of a filesystem verification step, so the workflow runs in any isolated `act` invocation.
