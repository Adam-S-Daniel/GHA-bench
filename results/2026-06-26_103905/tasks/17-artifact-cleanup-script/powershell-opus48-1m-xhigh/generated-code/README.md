# Artifact Cleanup (PowerShell)

Applies retention policies to a set of build artifacts (mock metadata: name,
size, creation date, workflow run id), decides what to delete, and prints a
deletion plan with a summary (space reclaimed, retained vs deleted). Supports a
dry-run mode. Built test-first with Pester and exercised end-to-end through a
GitHub Actions workflow via [`act`](https://github.com/nektos/act).

## Layout

| Path | Purpose |
|------|---------|
| `ArtifactCleanup.psm1` | Core library (pure functions, fully unit-testable). |
| `Invoke-ArtifactCleanup.ps1` | CLI entry point used by the workflow. |
| `fixtures/*.json` | Mock artifact metadata + per-fixture policies. |
| `Tests/ArtifactCleanup.Tests.ps1` | Unit tests (red/green TDD). |
| `Tests/Workflow.Structure.Tests.ps1` | Static workflow checks (YAML, actionlint, paths). |
| `Tests/Workflow.Act.Tests.ps1` | Integration harness that runs the workflow through `act`. |
| `.github/workflows/artifact-cleanup-script.yml` | CI/CD pipeline. |
| `act-result.txt` | Captured output of the `act` run (generated by the harness). |

## Retention policies

Three independent policies are combined. An artifact is **retained only if it
survives all of them**; it is **deleted if any policy flags it**, and every
applicable reason is recorded.

1. **Max age** — delete artifacts strictly older than *N* days (the exact
   boundary is kept).
2. **Keep latest N per workflow** — artifacts are grouped by **Name**. In GitHub
   Actions the same workflow re-uploads an artifact under the same name on every
   run, so each Name is effectively one workflow's artifact "stream" and the
   `workflowRunId` distinguishes the runs. Within each stream the *N* newest runs
   are kept (by creation date, ties broken by the higher/newer run id).
3. **Max total size** — applied last, over only the survivors of policies 1–2.
   If the retained total still exceeds the cap, the oldest survivors are evicted
   first until it fits.

The reference "now" is injectable (`-Now`) so age math is deterministic in tests
and in CI (fixtures pin a `referenceDate`).

## Dry-run

`Invoke-ArtifactCleanup -DryRun` builds and prints the full plan but performs no
deletions (the delete side effect — `-DeleteAction`, a no-op by default since
this works on mock data — is never invoked). Without `-DryRun`, the delete action
runs once per deleted artifact.

## Running

```powershell
# Plan from a fixture (dry run)
pwsh ./Invoke-ArtifactCleanup.ps1 -FixturePath ./fixtures/standard.json -DryRun

# All tests (unit + structure + act integration)
Invoke-Pester ./Tests

# Fast tests only (skip the Docker/act suite)
Invoke-Pester ./Tests -ExcludeTagFilter Act
```

## CI/CD pipeline

`.github/workflows/artifact-cleanup-script.yml` runs on push, pull_request, a
weekly schedule, and manual `workflow_dispatch` (with a `dry_run` toggle):

- **`unit-tests`** runs the Pester suite; the **`cleanup-plan`** job `needs` it
  and only runs if the logic is verified.
- Steps use `actions/checkout@v4` and `shell: pwsh`, and run unchanged inside the
  `act` container (pwsh + Pester pre-installed).
- Least-privilege `permissions: contents: read`.

The integration harness builds a throwaway git repo, runs the workflow once with
`act push` (the cleanup job loops over every fixture, so a single run exercises
all test cases), saves the output to `act-result.txt`, and asserts the **exact**
expected counts and reclaimed sizes for each fixture, plus a `Job succeeded`
line per job.
