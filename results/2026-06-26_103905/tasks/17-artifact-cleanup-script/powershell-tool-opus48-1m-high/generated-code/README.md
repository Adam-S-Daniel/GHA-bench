# Artifact Cleanup (PowerShell)

Applies retention policies to a set of CI artifacts, decides which to delete,
and produces a deletion plan with a summary. Built test-first with Pester and
exercised end-to-end through GitHub Actions via `act`.

## Retention policies (all optional, applied in this order)

1. **`MaxAgeDays`** — delete artifacts older than N days.
2. **`KeepLatestPerWorkflow`** — within each `WorkflowRunId` group, keep only
   the N most-recently created artifacts; mark the rest for deletion.
3. **`MaxTotalSize`** — cap the total retained size (bytes). Of the artifacts
   that survived rules 1–2, delete **oldest-first** until the total fits.

Reasons accumulate per artifact, so a single artifact can be flagged by more
than one policy. Disabled policies (value `0`) are skipped.

> Grouping note: the supplied metadata only identifies a workflow by
> `WorkflowRunId`, so "per workflow" is implemented as "per WorkflowRunId".

## Files

| File | Purpose |
|------|---------|
| `ArtifactCleanup.psm1` | The cleanup engine (pure policy logic + helpers). |
| `ArtifactCleanup.Tests.ps1` | Pester unit tests (red/green/refactor). |
| `Invoke-Cleanup.ps1` | CLI front-end the CI workflow runs. |
| `fixtures/artifacts.json` | Mock artifact metadata. |
| `fixtures/policy.json` | Mock retention-policy settings. |
| `.github/workflows/artifact-cleanup-script.yml` | CI pipeline. |
| `WorkflowAct.Tests.ps1` | Workflow structure + `act` integration harness. |
| `act-result.txt` | Captured `act` output (generated by the harness). |

## Running

```bash
# Unit tests
pwsh -c "Invoke-Pester -Path ./ArtifactCleanup.Tests.ps1"

# CLI (dry-run shown; omit -DryRun to perform the mock deletions)
pwsh -File ./Invoke-Cleanup.ps1 -FixturePath fixtures/artifacts.json \
  -MaxAgeDays 30 -KeepLatestPerWorkflow 2 -DryRun

# Full workflow + act integration harness (runs the pipeline via act)
pwsh -c "Invoke-Pester -Path ./WorkflowAct.Tests.ps1"
```

The CLI prints a human-readable plan plus stable `RESULT_*` lines that the CI
harness asserts on exactly.

## Dry-run

`-DryRun` (or `"DryRun": true` in `policy.json`) builds the identical plan but
never invokes the delete action; the summary records `DryRun = true`.
