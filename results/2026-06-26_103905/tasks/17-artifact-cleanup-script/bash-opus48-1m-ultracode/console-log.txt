## Summary

I built an **artifact retention-policy engine** in Bash using red/green TDD, with all functional testing flowing through a GitHub Actions pipeline via `act`.

### What was built
- **`artifact-cleanup.sh`** — applies three retention policies in deterministic order (the size cap operates on survivors):
  1. `--max-age-days N` — delete artifacts older than N days
  2. `--keep-latest N` — keep the N newest artifacts per workflow run id, delete the rest
  3. `--max-total-size BYTES` — cap retained size, deleting oldest-first to fit
  
  Plus a deletion plan + summary (space reclaimed, retained vs deleted), **dry-run default** / `--execute`, a pinnable `--now` for deterministic ages, self-describing `# policy:` fixture headers, a machine-readable `RESULT` line, and graceful errors (missing/bad input, malformed records, bad dates/sizes — all exit 1 with meaningful messages).
- **4 fixtures** (`fixtures/case*.txt`) — one per policy plus a combined case, each with hand-computed expected results documented inline.
- **`.github/workflows/artifact-cleanup-script.yml`** — triggers on `push`/`pull_request`/`schedule`/`workflow_dispatch`; per-job permissions; env vars; two jobs with a dependency (`cleanup` → `report`); checkout@v4; dependency-verify + shellcheck-lint steps; self-validates each case's exact output and exposes aggregate job outputs.
- **`test/artifact-cleanup.bats`** — 21 tests: 11 structure/lint checks + 10 act-driven pipeline assertions on exact values.

### Key design decision
Since each `act push` takes 30–90s and the budget is ≤3 runs, the workflow processes **every test case in a single `act push`** invocation. `setup_file` runs act once, captures to `act-result.txt`, and each test asserts exact values from that shared capture — so all cases flow through the real pipeline while staying within budget. **I used only 1 of the 3 allowed act runs.**
