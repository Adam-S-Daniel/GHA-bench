## Solution Overview

A PowerShell artifact-retention tool built **red/green TDD** with Pester, wired into a GitHub Actions workflow that's verified end-to-end through `act`.

### What it does
Given artifacts (`name`, `sizeBytes`, `createdAt`, `workflowRunId`), it composes three optional retention policies:
1. **`maxAgeDays`** — delete artifacts older than N days (boundary day kept)
2. **`keepLatestN`** — per `workflowRunId` group, keep the N newest, delete the rest
3. **`maxTotalSizeBytes`** — of the survivors, evict oldest-first until under the cap

An artifact is deleted if *any* policy objects (reasons union, e.g. `MaxAge|KeepLatestN`), and it emits a deletion plan + summary (space reclaimed, retained vs deleted). **Dry-run is the safe default.**

### TDD process (7 visible red→green cycles)
empty-plan → `MaxAge` → `KeepLatestN` → `MaxTotalSize` → policy composition + input validation → `Invoke-ArtifactCleanup` dry-run/execution → JSON import + report rendering. Each cycle: failing test first, minimum code, green.

### Key design choices
- Self-contained JSON fixture (`policies` + `referenceDate` + `dryRun` + `artifacts`) fully determines each run, keeping the workflow static while the harness varies only the data
- A fixed `referenceDate` + UTC normalization make age-based output deterministic and timezone-independent

- The pure engine never deletes — `Invoke-ArtifactCleanup` calls a caller-supplied delete action (skipped in dry-run), keeping the dangerous side effect out of the testable core
