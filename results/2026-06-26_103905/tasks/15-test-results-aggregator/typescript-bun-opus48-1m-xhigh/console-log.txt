## Summary

I built a dependency-free TypeScript/Bun **test-results aggregator** using red/green TDD, wired it into a GitHub Actions workflow, and validated the whole pipeline end-to-end through `act`.

### What was built

**Library (`src/`)** — each module developed test-first (wrote a failing test, confirmed red, implemented to green):
- `types.ts` — format-agnostic domain types (`TestCase`, `TestRun`, `Totals`, `FlakyTest`, `Aggregate`).
- `parser.ts` — JUnit **XML** parser (handles `<testsuites>`/bare `<testsuite>`, self-closing cases, `<failure>`/`<error>`/`<skipped>`, entity decoding) and a flexible **JSON** parser (array or `{tests:[...]}`, status-synonym normalization). Meaningful errors on malformed input.
- `aggregator.ts` — totals (passed/failed/skipped/total/duration) + flaky detection (passed in some runs *and* failed in others; skips don't count), deterministically sorted.
- `markdown.ts` — GitHub job-summary Markdown + a delimited `=== AGGREGATE SUMMARY ===` key=value block for reliable CI assertions.
- `cli.ts` — reads files/dirs, writes to `$GITHUB_STEP_SUMMARY` + stdout, graceful errors, skips bad files without aborting.

**Tests** — `bun test` → **48 pass, 2 skip, 0 fail** (the 2 skips are the act suite, guarded by `RUN_ACT`):

- `workflow.test.ts` — parses the YAML (via `Bun.YAML`), asserts triggers/jobs/steps, verifies referenced script paths exist, and asserts `actionlint` exits 0.
- `act.integration.test.ts` — the end-to-end harness.

**Workflow** (`.github/workflows/test-results-aggregator.yml`) — triggers on push/pull_request/schedule/workflow_dispatch; `permissions: contents: read`; concurrency group; checkout → setup-bun → unit tests → aggregate. **actionlint passes (exit 0).**
