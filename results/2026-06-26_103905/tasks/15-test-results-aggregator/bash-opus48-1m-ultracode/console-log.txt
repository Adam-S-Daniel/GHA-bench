## What I built

A pure-Bash test-results aggregator developed red→green with bats, fully exercised through a GitHub Actions workflow via `act`.

**`aggregate-test-results.sh`** — parses **JUnit XML** (portable awk tag-stream walker, no `xmllint`) and **JSON** (`jq`), normalizes every test case to `status⇥test-id⇥duration`, then in one awk pass computes totals (passed/failed/skipped/duration) and detects **flaky** tests (a `classname.name` that both passed *and* failed across matrix legs). Emits Markdown for `$GITHUB_STEP_SUMMARY` plus an optional `key=value` counts file. Handles errors gracefully (missing path, no files, malformed input, missing `jq`) with distinct exit codes.

**Fixtures** — a committed 3-leg matrix sample (`fixtures/`: ubuntu XML, macos XML, windows JSON) plus per-scenario sets under `tests/scenarios/`.

**`.github/workflows/test-results-aggregator.yml`** — triggers on push/pull_request/schedule/workflow_dispatch; `contents: read` permissions; `env.RESULTS_DIR`; an `aggregate` job (checkout → ensure jq → run script → publish summary → export job outputs) and a dependent `gate` job (`needs:`) that consumes the outputs and fails on zero tests.
