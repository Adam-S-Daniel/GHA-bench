# Secret Rotation Validator

A TypeScript/Bun tool that reads a configuration of secrets with metadata
(name, last-rotated date, rotation policy in days, required-by services),
identifies secrets that are **expired** or **expiring within a configurable
warning window**, and produces a rotation report plus notifications grouped by
urgency. It supports **markdown table**, **JSON**, and a **GitHub-output**
format for CI integration.

Built with red/green TDD using Bun's built-in test runner.

## Files

| File | Purpose |
| --- | --- |
| `secret-rotation-validator.ts` | Library + CLI: classification, report, formatters, arg parsing. |
| `secret-rotation-validator.test.ts` | Unit tests (pure logic, parsing, formatters, CLI). |
| `workflow.test.ts` | Workflow structure tests **+** `act` integration (every case runs through the pipeline). |
| `fixtures/*.json` | Mock secret configs used as test fixtures. |
| `.github/workflows/secret-rotation-validator.yml` | CI pipeline that runs the validator. |
| `act-result.txt` | Captured `act` output for every integration case (generated by the tests). |

## Usage

```bash
# Markdown report (default)
bun run secret-rotation-validator.ts --config fixtures/secrets.json

# JSON report
bun run secret-rotation-validator.ts --config fixtures/secrets.json --format json

# Override the warning window, gate CI on expired secrets
bun run secret-rotation-validator.ts -c fixtures/secrets.json -w 30 --fail-on expired

# Print urgency-grouped notifications (to stderr)
bun run secret-rotation-validator.ts -c fixtures/secrets.json --notify
```

### Options

| Flag | Description | Default |
| --- | --- | --- |
| `-c, --config <path>` | Secrets JSON config (required). | — |
| `-f, --format <fmt>` | `markdown` \| `json` \| `github`. | `markdown` |
| `-w, --warning-days <n>` | Warning window in days. | config value or `14` |
| `--now <YYYY-MM-DD>` | Evaluation date (for determinism/testing). | config value or today |
| `--fail-on <level>` | Exit non-zero when findings reach `none`/`warning`/`expired`. | `none` |
| `--notify` | Also print grouped notifications to stderr. | off |
| `-h, --help` | Show help. | — |

Precedence for each setting: **CLI flag → environment variable → config file →
built-in default**. Environment variables: `SECRET_ROTATION_CONFIG`,
`SECRET_ROTATION_NOW`, `SECRET_ROTATION_WARNING_DAYS`, `SECRET_ROTATION_FORMAT`,
`SECRET_ROTATION_FAIL_ON`, `SECRET_ROTATION_NOTIFY`.

### Config format

```json
{
  "now": "2026-06-28",
  "warningWindowDays": 14,
  "secrets": [
    {
      "name": "db-password",
      "lastRotated": "2026-01-01",
      "rotationPolicyDays": 90,
      "requiredBy": ["api-server", "worker"]
    }
  ]
}
```

`now` and `warningWindowDays` are optional in the file (they make a fixture
self-describing for deterministic CI). A bare JSON array of secrets is also
accepted as shorthand.

### Classification

For each secret, `expiryDate = lastRotated + rotationPolicyDays` and
`daysUntilExpiry = whole days from now to expiryDate`:

- **expired** — `daysUntilExpiry <= 0` (due today or overdue)
- **warning** — `0 < daysUntilExpiry <= warningWindowDays`
- **ok** — `daysUntilExpiry > warningWindowDays`

## Testing

```bash
bun test
```

This runs the unit tests, the workflow structure tests, and the `act`
integration cases. Each integration case builds a temp git repo, runs
`act push` in Docker, and asserts the exact expected values. All `act` output is
written to `act-result.txt`. (`act` + Docker must be available.)

## CI workflow

`.github/workflows/secret-rotation-validator.yml` runs on push, pull_request, a
weekly schedule, and manual dispatch. The `validate` job classifies secrets and
exposes per-urgency counts/names as job outputs; the dependent `notify` job
prints the urgency-grouped notifications. A manual dispatch can set `fail_on` to
make rotation drift fail the pipeline.
