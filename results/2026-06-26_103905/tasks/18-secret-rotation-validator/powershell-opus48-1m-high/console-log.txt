## Solution overview

Built a **Secret Rotation Validator** in PowerShell using red/green TDD, then wired it into a real GitHub Actions pipeline verified end-to-end with `act`.

### TDD progression (6 red→green cycles)
1. `Get-SecretRotationStatus` — single-secret urgency classification (expired/warning/ok)
2. Warning/ok/boundary classification + error handling
3. `Get-SecretRotationReport` — aggregation, grouping, summary, sorting
4. `Format-RotationReport` — markdown table + JSON output
5. `Import-SecretConfig` — JSON config loading (array or `{secrets:[...]}` wrapper) with clear errors
6. `Invoke-Validator.ps1` — CLI entrypoint with env-var fallbacks and a `-FailOnExpired` CI gate

Each piece started with a failing test (verified RED), then minimum code to pass (GREEN).

- **46 Pester tests pass** locally (30 unit + 16 workflow-structure), runnable via `Invoke-Pester`
- **actionlint passes cleanly** (exit 0)
- **All 3 act test cases pass** through the real pipeline — `mixed-urgency`, `all-ok`, `warning-only` — each asserting exact summary counts, exact gate status, secret names, in-pipeline Pester success, both jobs `Job succeeded`, and act exit 0
- **`act-result.txt`** generated (687 lines) ending in `RESULT: ALL ACT TESTS PASSED`

### Workflow design
Two jobs: `unit-tests` (runs the Pester suite) → `validate` (`needs: unit-tests`, generates markdown + JSON reports and a report-only rotation gate). Triggers: push, pull_request, schedule (daily cron), workflow_dispatch with inputs. Least-privilege `contents: read`, pinned `REFERENCE_DATE` for determinism, `shell: pwsh` on every run step, `actions/checkout@v4`.

### One real bug found and fixed via diagnosis (not blind re-runs)
The first act run exposed that the gate step's `$LASTEXITCODE` leaked the validator's `exit 2` through GitHub's pwsh step wrapper (Write-Host doesn't reset it), failing the `validate` job. Fixed by adding explicit `exit 0` to the report-only branches — confirmed green on the next run.
