# Secret Rotation Validator

A PowerShell tool that reads a configuration of secrets (name, last-rotated date,
rotation policy in days, and the services that require each secret), determines
which secrets are **expired** or **expiring within a configurable warning window**,
and emits a rotation report grouped by urgency (**Expired / Warning / Ok**) in
either **Markdown** or **JSON**.

Built test-first with Pester (red → green → refactor).

## Files

| File | Purpose |
|------|---------|
| `SecretRotationValidator.ps1` | Implementation + CLI entry point (dot-sourceable for tests). |
| `SecretRotationValidator.Tests.ps1` | Pester unit tests for every function. |
| `WorkflowStructure.Tests.ps1` | Parses the workflow YAML and asserts triggers/jobs/steps + runs actionlint. |
| `Act.Tests.ps1` | End-to-end harness: runs every test case through the workflow via `act`. |
| `secrets.json` | Default sample configuration. |
| `fixtures/*.json` | Per-case fixtures (mixed / all-ok / all-expired). |
| `.github/workflows/secret-rotation-validator.yml` | CI/CD pipeline. |
| `act-result.txt` | Captured `act` output for every test case (generated by `Act.Tests.ps1`). |

## Usage

```pwsh
# Markdown report (default)
./SecretRotationValidator.ps1 -ConfigPath secrets.json -WarningDays 7

# JSON report, with an explicit "now" for deterministic output
./SecretRotationValidator.ps1 -ConfigPath secrets.json -Format Json -ReferenceDate 2026-06-26
```

### Config format

```json
{
  "secrets": [
    { "name": "db-password", "lastRotated": "2026-01-01", "rotationPolicyDays": 90, "requiredBy": ["api", "worker"] }
  ]
}
```

A secret is **Expired** when its expiry (`lastRotated + rotationPolicyDays`) is in
the past, **Warning** when it expires within `WarningDays` (inclusive), otherwise **Ok**.

## Running the tests

```pwsh
# Unit + structure tests (fast)
Invoke-Pester -Path ./SecretRotationValidator.Tests.ps1,./WorkflowStructure.Tests.ps1

# Full end-to-end pipeline tests via act (slow; requires Docker + act)
Invoke-Pester -Path ./Act.Tests.ps1
```

## CI/CD

The workflow runs on push, pull_request, a daily schedule, and manual dispatch. It
has two jobs: `test` (Pester unit tests) and `report` (which `needs: test` and
generates the Markdown + JSON reports). All `run:` steps use `shell: pwsh`.
