## What was built

**`matrix_generator.py`** — a stdlib-only Python script that turns a config (OS / language / feature-flag axes) into a GitHub Actions build matrix, using the *dynamic matrix* idiom (`{"include": [...fully-expanded combos...]}`) so each entry becomes one job via `fromJson`.

Supported config: `axes`, `exclude` (partial-match removal), `include` (faithful to GitHub's documented algorithm — merge into matching original combos without overwriting axis values, else append as a new combo), `max_parallel`, `fail_fast`, and `max_size` (hard cap → fails with a clear error if exceeded). The CLI emits the matrix JSON, exits non-zero with meaningful stderr messages for missing file / bad JSON / size violations.

## TDD methodology

Wrote `test_matrix_generator.py` first → confirmed RED (`ModuleNotFoundError`) → implemented the module → GREEN. Tests grow from the smallest unit (cartesian product) outward through exclude/include (incl. the canonical GitHub docs example), size validation, strategy passthrough, and the CLI.

## GitHub Actions workflow

`.github/workflows/environment-matrix-generator.yml`:
- Triggers: `push`, `pull_request`, `schedule`, `workflow_dispatch` (with a config-path input)
- `permissions: contents: read`; `env.CONFIG_FILE`
- **Job 1** `generate-matrix`: checkout → run script → expose matrix as a job output + greppable markers
- **Job 2** `build` (`needs: generate-matrix`): real dynamic `strategy.matrix: ${{ fromJson(...) }}` — each combo runs as its own job
- **actionlint: passes clean (exit 0)**

## Testing through act

`test_workflow.py` has structure tests (YAML triggers/jobs/dependency/checkout@v4/script-path, actionlint exit 0) plus an act harness that, per fixture, builds a temp git repo, runs `act push --rm`, appends delimited output to **`act-result.txt`**, and asserts on **exact** values — e.g. `MATRIX_SIZE=4`, the precise compact matrix JSON, `FAIL_FAST=false`/`MAX_PARALLEL=2`, ≥4 expanded `COMBO_DONE` jobs, and `Job succeeded` per job.
