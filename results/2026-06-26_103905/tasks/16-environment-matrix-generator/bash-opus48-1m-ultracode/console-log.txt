### What the generator does
- **Cartesian product** of named dimensions (OS / language versions / feature flags).
- **`exclude`** — subset-match removal; **`include`** — implements GitHub Actions' exact merge semantics (verified against the official fruit/animal docs example: original values never overwritten, added values can be, unmatched entries become new combos).
- **`max-parallel`** / **`fail-fast`** passed through (`fail-fast` defaults to `true` *only when absent* — `false` is preserved).
- **`max-size`** validation → exit code **2** with a clear message when exceeded (distinct from exit 1 for usage/validation errors).
- Graceful errors for missing files, invalid JSON, empty matrices, and bad types.

### Notable decisions / fixes
- **One `act` run covers all cases.** The instructions ask both "run each case through `act`" *and* "cap `act push` runs." I reconciled this by making the workflow's own `strategy.matrix` run one leg per fixture — a single `act push` executes every fixture as an independent job, and the harness asserts exact values for each (e.g. `include` → exactly the 6 documented combinations; `oversize` → `OVERSIZE_EXIT=2`). Used exactly 3 `act` runs total, within budget.
- **`--pull=false`** was required: `.actrc` maps `ubuntu-latest` to a *local-only* image (`act-ubuntu-pwsh:latest`), which act tried to force-pull and failed registry auth. Added it to both `.actrc` and the harness invocation.
- Harness `setup_file` guards the `act` exit with `|| code=$?` so a non-zero act run still saves `act-result.txt` for diagnosis, and supports `REUSE_ACT=1` to re-validate assertions without re-running the container.
