## Approach

I followed strict **red/green TDD** — writing a failing test, then the minimum code to pass it, for each piece of functionality, in this order: `parse_version` → `validate_version` → `determine_bump` → `bump_version` → `update_version_file` → `generate_changelog` → `main` (CLI). The script guards `main()` behind `BASH_SOURCE == $0` so tests can `source` it and exercise functions in isolation.

## Deliverables

- **`semver-bump.sh`** — the tool. Reads a version from a `VERSION` file *or* `package.json` (sed-based, no jq dependency), maps conventional commits to bumps (`feat!`/`BREAKING CHANGE:`→major, `feat`→minor, `fix`→patch, highest wins), updates the file, prepends a Keep-a-Changelog entry, prints the new version to stdout. Errors go to stderr with meaningful messages; `--dry-run` and `--help` supported.
- **`test/semver-bump.bats`** — 24 unit tests covering every function plus end-to-end CLI cases.
- **`fixtures/`** — six mock commit-log + version-file scenarios (patch, minor, major, package.json, breaking-footer, none).
- **`.github/workflows/semantic-version-bumper.yml`** — push / pull_request / schedule / workflow_dispatch triggers, `contents: read` permissions, and a **job matrix** that runs each fixture case as its own job (checkout → run script → assert exact version → show changelog).
- **`test/workflow.bats`** — 12 structure tests (triggers, jobs, steps, script/fixture path existence, actionlint exit 0, expected-version consistency).
- **`run-act-tests.sh`** — integration harness: stages a temp git repo, runs `act push --rm` once over the whole matrix, saves the full log to **`act-result.txt`**, and asserts act exit 0, each case's **exact** expected version, and one `Job succeeded` per job.
