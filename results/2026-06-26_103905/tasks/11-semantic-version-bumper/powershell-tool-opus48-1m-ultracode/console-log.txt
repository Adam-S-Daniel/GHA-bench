## What was built (red/green TDD throughout)

**Core logic — `SemanticVersionBumper.psm1`** (8 small, individually-tested functions):
- `Get-CurrentVersion` — reads a plain `VERSION` file or `package.json` (tolerates `v` prefix)
- `ConvertFrom-ConventionalCommit` — parses `type(scope)!: desc`, detects breaking via `!` or `BREAKING CHANGE`
- `Get-CommitBumpType` — precedence: breaking→major, feat→minor, fix→patch, else none
- `Get-NextVersion` — steps the version, resetting lower components
- `New-ChangelogEntry` — grouped Markdown (Breaking / Features / Bug Fixes / Other)
- `ConvertFrom-CommitLog`, `Set-VersionFile` (regex-preserves package.json layout), `Invoke-VersionBump` (orchestrator)

**`Invoke-VersionBump.ps1`** — CLI the workflow calls: resolves inputs from params→env→defaults, emits `NEW_VERSION=…` markers, writes `$GITHUB_OUTPUT` and a job summary, fails with a meaningful error.

**`.github/workflows/semantic-version-bumper.yml`** — push/pull_request/schedule/workflow_dispatch triggers, least-privilege permissions, two jobs with a dependency (`bump` → `verify`), `actions/checkout@v4`, `shell: pwsh`, runs in-container Pester then the bumper, propagates the version via job outputs.

**Fixtures** — mock commit logs for minor/patch/major cases plus root defaults.
