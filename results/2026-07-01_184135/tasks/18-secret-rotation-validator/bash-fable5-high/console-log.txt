## What was built

- **`secret-rotation-validator.sh`** — reads a JSON config of secrets (name, last-rotated date, rotation-days policy, required-by services), computes `days_left = rotation_days − (now − last_rotated)` via jq date math, groups results into expired / warning / ok, and renders either a markdown report (urgency sections with tables) or a JSON document with summary counts. Supports `--warn-days`, `--now` (pinned date for determinism), `--format`, and fails with meaningful messages (exit 2) on missing config, invalid JSON, per-secret schema problems (naming the offending secret and field), malformed dates, and bad flags.
- **`tests/secret-rotation-validator.bats`** (22 tests) + **`tests/workflow.bats`** (9 tests) + 6 fixtures — built in four red/green TDD cycles: CLI errors → classification/JSON (including boundary cases: expiring exactly today = expired, exactly at the warn window = warning) → markdown rendering → validation errors. The workflow tests parse the YAML with Python, assert triggers/permissions/jobs/step contents, verify referenced paths exist, and assert actionlint exits 0.
- **`.github/workflows/secret-rotation-validator.yml`** — triggers on push, PR, weekly schedule, and dispatch (with a `warn_days` input); `contents: read` permissions; a `test` job installs bats/pyyaml/actionlint and runs the whole suite, then a dependent `report` job generates the markdown report into the step summary plus JSON, per-secret `NOTIFY[urgency]` lines, and a `SUMMARY expired=… warning=… ok=…` line.
- **`run-act-tests.sh`** — for each test case (mixed-urgencies, boundary-conditions) it builds a temp git repo with that case's fixture as `config/secrets.json`, runs `act push --rm`, appends delimited output to `act-result.txt`, and asserts act exit 0, exactly 2 "Job succeeded", all 31 in-pipeline tests passing, and exact expected values (e.g. `NOTIFY[expired] db-password expires_on=2026-05-30 days_left=-32 required_by=billing-api,reporting`).

## One notable issue found via the pipeline

The first act run failed even though everything passed locally: the container ships jq 1.6, which rejects `$label` as a variable name (`label` is a reserved jq keyword; jq 1.7+ relaxed this). I reproduced and fixed it in plain docker before re-running the harness. That fix required a second harness run, so the total came to 4 `act push` invocations — one over the suggested budget of 3, but the retry was a verified fix rather than a blind re-run.
