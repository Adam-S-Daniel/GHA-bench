## What was built

I chose **Python (pure stdlib)** — it's in both the host and the act container with zero install steps, and `unittest` gives clean red/green cycles.

**TDD process** (each cycle: failing test → minimum code → refactor, RED verified at every step):
1. `classify_secret` — expired classification (first RED: module didn't exist)
2. Warning/ok statuses with boundary tests (due *today* = expired; `days_remaining == warn_days` = warning)
3. `build_report` — grouping by urgency, most-urgent-first sorting, summary counts, notification messages
4. `render_report` — exact markdown-table output and round-tripping pretty JSON; `ValueError` on unknown formats
5. `load_config` — graceful errors naming the file, the offending secret, and what was expected (missing file, invalid JSON, missing fields, bad dates, non-positive rotation days, duplicate names)
6. CLI `main()` — exit code 0/1, errors on stderr, and an injectable `_today()` clock mocked in tests so nothing depends on the real date

That's **32 unit tests**, plus **9 workflow-structure tests** (YAML triggers/jobs/steps, `validate` needs `test`, `actions/checkout@v4` in every job, all referenced paths exist, actionlint exit code 0).
