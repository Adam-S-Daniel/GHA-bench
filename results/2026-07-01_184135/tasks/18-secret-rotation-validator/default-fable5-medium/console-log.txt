**What I built (Python, stdlib only — zero install steps needed in CI):**

- `secret_rotation_validator.py` — the validator. Loads a JSON config of secrets (name, last-rotated date, rotation policy in days, required-by services), classifies each as **expired** (expiry date reached), **warning** (within the configurable warn window), or **ok**, and renders the report as a markdown table or JSON. The CLI supports `--config`, `--format markdown|json`, `--warn-days`, `--today` (deterministic reference date for testing), and `--fail-on-expired` (exit code 2). All config errors surface as clear `ConfigError` messages naming the bad field.
- `test_secret_rotation_validator.py` — 25 unit tests built in five red/green TDD cycles (classification → config validation → report grouping → output formats → CLI). Each cycle I ran the test, watched it fail, then implemented the minimum to pass.
- `test_workflow_structure.py` — 7 structure tests that parse the workflow YAML and assert triggers, least-privilege permissions, the `report → test` job dependency, that every referenced file exists, and that actionlint exits 0.
- `fixtures/` — designed up front: `case1-mixed.json` (one secret per urgency bucket) and `case2-boundaries.json` (expires exactly today → expired; expires exactly at the 14-day boundary → warning), plus a default `secrets.json`.
- `.github/workflows/secret-rotation-validator.yml` — triggers on push, pull_request, workflow_dispatch, and a weekly schedule; `contents: read` permissions; a `test` job running the unit suite and a dependent `report` job emitting the markdown report, JSON report, and per-secret `NOTIFY` lines. Passed actionlint on the first attempt.
- `run_act_tests.sh` — the act harness. For each case it builds a temp git repo with the project files plus that case's fixture installed as `fixtures/secrets.json`, runs `act push --rm`, appends the delimited output to `act-result.txt`, and asserts exit code 0, two "Job succeeded" lines, and exact expected values (e.g. `SUMMARY expired=1 warning=1 ok=1 total=3` and the literal markdown row `| EXPIRED | db-password | 2026-06-21 | -10 | billing-api, reporting |`).
