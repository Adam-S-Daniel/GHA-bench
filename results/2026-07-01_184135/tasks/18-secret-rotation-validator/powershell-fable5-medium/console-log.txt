**What was built**

- `SecretRotationValidator.ps1` — the validator. Loads a JSON secrets config (name, lastRotated, rotationDays, requiredBy), computes each secret's expiry (lastRotated + rotationDays), and classifies it as `expired` (deadline reached), `warning` (within the configurable window, inclusive at the edge), or `ok`. Reports are grouped by urgency, most urgent first, in markdown-table or JSON format. It takes an injectable `-ReferenceDate` so all date math is deterministic, and `-FailOnExpired` for use as a CI gate (exit 2). Errors are validated up front with messages naming the offending secret and field. Dot-sourcing with no arguments loads just the functions, which is how the tests consume it.
- `fixtures/secrets.json` (2 expired / 2 warning / 1 ok at the pinned date) and `fixtures/secrets-ok.json` (all ok).
- `tests/SecretRotationValidator.Tests.ps1` — 28 unit tests built red/green: classification incl. both boundary cases (expires today → expired; expires exactly at window edge → warning), config validation errors, grouping/sorting, exact markdown and JSON output, and CLI exit codes exercised in a child pwsh process.
- `.github/workflows/secret-rotation-validator.yml` — push/PR/weekly-schedule/dispatch triggers, `contents: read` permissions, a `test` job running Pester and a dependent `report` job that emits the markdown report (also to the job summary), the JSON report, and a stable `ROTATION-SUMMARY expired=… warning=… ok=…` line the harness asserts on. All run steps use `shell: pwsh`.
- `tests/Workflow.Tests.ps1` — structure tests (YAML parse of triggers/jobs/needs/permissions, script paths exist, actionlint exit 0) plus the act harness: per case it builds a temp git repo, runs `act push --rm`, appends delimited output to `act-result.txt`, and asserts exit 0, every job succeeded, and exact known-good values.

- Dot-sourcing the script also imports its `param()` defaults, so an empty `$ConfigPath` shadowed the test variable of the same name — the CLI tests silently ran with no config. Fixed by renaming the test variables (documented in a comment).
- The first harness design overwrote `fixtures/secrets.json` per case, which broke the in-container unit tests that assert on that fixture. Reworked so the workflow's config path is `${{ vars.SECRETS_CONFIG || 'fixtures/secrets.json' }}` and each act case selects its fixture with `--var`, leaving fixtures untouched. (Also added `--pull=false` since the runner image is local-only.)
