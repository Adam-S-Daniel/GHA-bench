## Summary

Built a PR label assigner in Bash using red/green TDD (each feature started with a failing bats test), with all end-to-end testing routed through the GitHub Actions workflow via `act`.

**How it works** — `label-assigner.sh` reads a changed-file list (via `-f` or stdin, mocking a PR diff) and a rules file of `priority|glob|label1,label2[|stop]` lines. Globs support `**` (crosses directories), `*`/`?` (single segment), and gitignore-style basename matching for patterns without `/` (so `*.test.*` matches nested test files). Rules are evaluated per file in priority order (lower number first); all matching rules contribute labels, but a matching `stop` rule ends evaluation for that file, which is how conflicts are resolved. Output is the sorted, deduplicated label set. Errors (missing files, malformed rules with line numbers, bad flags) exit 2 with clear messages; zero matches is a clean exit 0 with a stderr notice.

**Test results**
- 16 unit tests + 10 workflow-structure tests, all passing (`bats tests/`).
- The structure tests parse the YAML with PyYAML and assert triggers, jobs, `needs:` dependency, `checkout@v4`, permissions, script references, and that every referenced path exists; actionlint asserted to exit 0.
- `shellcheck` and `bash -n` clean on all scripts; `actionlint` clean on the workflow.

**CI pipeline** — `.github/workflows/pr-label-assigner.yml` has two jobs: `test` (installs bats-core via npm, runs the full unit suite) and `assign-labels` (`needs: test`, runs the script against fixture data, exposes the label set via `$GITHUB_OUTPUT` between parseable markers, and reports it as a dry run so no secrets are needed).

**act harness** — `run-act-tests.sh` ran 3 cases, each in a fresh temp git repo through `act push --rm`: basic mapping (asserted exactly `api,backend,documentation,tests`), priority conflict (exactly `api,documentation`, with the suppressed `markdown` label asserted absent), and no-match (exactly empty set plus the notice). All cases: act exit 0 and both jobs showing "Job succeeded". Full output is in `act-result.txt`. The only hiccup was act force-pulling the local-only runner image (instant registry-auth failure) — fixed with `--pull=false`, and the single re-run passed everything.
