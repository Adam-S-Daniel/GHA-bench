## What was built

A TypeScript/Bun test-results aggregator, developed with red/green TDD (each `tests/*.test.ts` was written first and run to a failing state before its module existed — the cycle is documented in each test file's header):

- **`src/parsers/junit.ts`** — dependency-free JUnit XML parser (handles self-closing and paired `<testcase>` elements, `<failure>`/`<error>`/`<skipped>` children, entity decoding, meaningful errors naming the offending file).
- **`src/parsers/json.ts`** — parser for a simple documented JSON schema, with per-entry validation errors.
- **`src/aggregate.ts`** — aggregates runs by test identity (`suite > name`), computes totals (passed/failed/skipped/duration), and classifies **flaky** (passed in ≥1 run *and* failed in ≥1 run) vs. consistently **failing** tests. Skips never count toward flakiness.
- **`src/markdown.ts`** — GitHub job-summary markdown: headline verdict, totals table, flaky/failing tables (omitted when empty), per-run breakdown, pipe-escaping for table safety.
- **`src/cli.ts`** — discovers `.xml`/`.json` files in a directory, prints a greppable `AGGREGATE_RESULT ...` line plus the markdown, and appends to `$GITHUB_STEP_SUMMARY`.
- **`fixtures/case1`** (3-shard matrix with a flaky test and a real failure) and **`fixtures/case2`** (all green) serve as both unit-test data and act pipeline inputs.

## Pipeline validation

The workflow (`.github/workflows/test-results-aggregator.yml`) has `push`/`pull_request`/`workflow_dispatch` triggers, `contents: read` permissions, and two jobs: `unit-tests` (installs Bun + actionlint, runs `bun test` — including workflow-structure tests that parse the YAML, verify referenced paths exist, and assert actionlint exits 0) and `aggregate` (`needs: unit-tests`, runs the CLI over `results/` with a fixture fallback).
