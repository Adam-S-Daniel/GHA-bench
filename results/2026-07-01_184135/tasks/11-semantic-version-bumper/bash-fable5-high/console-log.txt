## What was built

**`bump_version.sh`** — reads a version from a plain `VERSION` file or `package.json` (no jq dependency), scans a commit log for conventional commits (`type!:`/`BREAKING CHANGE` → major, `feat` → minor, `fix` → patch, otherwise no bump), rewrites the version file in place, prepends a grouped changelog entry (Breaking Changes/Features/Fixes), and prints the new version as the last stdout line. In CI it also writes `old_version`/`new_version`/`bump_type` to `$GITHUB_OUTPUT`. Errors (missing file, malformed version, unknown flags) exit non-zero with clear messages.

**TDD process** — 7 red/green cycles, each verified with a failing bats run before implementing: version reading → package.json support → bump detection → version arithmetic → file writeback → changelog rendering/prepending → end-to-end CLI. 27 unit tests in `tests/bump_version.bats` plus 4 workflow-structure tests in `tests/workflow.bats` (actionlint exit code, PyYAML-based structure checks of triggers/jobs/steps/`needs`, and referenced-path existence). Mock commit logs live in `tests/fixtures/` (feat, fix, breaking-bang, breaking-footer, none).

**Workflow** (`.github/workflows/semantic-version-bumper.yml`) — `push`/`workflow_dispatch` triggers, `permissions: contents: read`, two jobs chained with `needs`: `unit-tests` installs bats and runs the full suite; `bump-version` runs the script against `ci-fixture/` and asserts the result matches the fixture's expected version.
