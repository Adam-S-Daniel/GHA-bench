## Summary

Built a PowerShell dependency license checker in `powershell-sonnet5/` using red/green TDD:

- **`LicenseChecker.psm1`** — `Get-ManifestDependency` (parses package.json/requirements.txt), `Get-PackageLicense` (mockable license lookup), `Resolve-LicenseStatus` (allow/deny classification, deny-wins fail-safe), `New-LicenseComplianceReport` (orchestrator)
- **`Invoke-LicenseCheck.ps1`** — CLI entry point printing a report + `Summary: Approved=X, Denied=Y, Unknown=Z` line; exits 0 on a successful report (even with denied licenses found) and 1 with a clear message on genuine errors (missing/malformed files)
- **`tests/`** — 37 Pester tests total: unit tests with mocked license lookups (`LicenseChecker.Tests.ps1`), CLI behavior tests (`InvokeLicenseCheck.Tests.ps1`), and workflow-structure tests (`WorkflowStructure.Tests.ps1`) that check triggers/jobs/permissions and run `actionlint`
- **`.github/workflows/dependency-license-checker.yml`** — push/pull_request/schedule/workflow_dispatch triggers, `contents: read` permission, two jobs (`test` → `compliance-report` via `needs:`), all steps using `shell: pwsh`; passes `actionlint` cleanly
- **`run-act-tests.ps1`** — acceptance harness that spins up isolated temp git repos for 3 fixture scenarios (all-approved, with-denied-license, with-unknown-license), runs `act push --rm --pull=false` for each, and asserts exact summary values + "Job succeeded" for both jobs
- **`act-result.txt`** — the required artifact; all 3 cases show exit code 0 and exact expected summaries

One snag: `act`'s default force-pull tried to fetch the locally-built `act-ubuntu-pwsh:latest` image from a registry and failed on auth. Fixed with `--pull=false` since the image is local-only, verified once, then ran the full 3-case harness (used one extra diagnostic run beyond the nominal 3, all caused by that single config issue rather than blind retries).
